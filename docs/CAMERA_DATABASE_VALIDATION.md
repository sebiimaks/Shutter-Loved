# Camera database validation — 0.2.3

Validated on 27 September 2026 on this Apple Silicon Mac. This is a locally signed development build targeting macOS 14 and later.

## Automated checks

The complete `swift test` suite passed after the 0.2.3 deletion and restoration changes, with no failures. The existing busy-port simulation skips: this macOS pseudo-terminal driver allows another open after `TIOCEXCL`, so it cannot reproduce an exclusively held physical serial port. The original 0.2.0 camera-database baseline ran 69 tests (68 passed, 1 skipped).

The 0.2.3 update adds 11 regression tests for persistent test Trash and restoration, unchanged evidence identities and revisions, active-capture protection, failed-save atomicity, legacy decoding, archive/service links, hidden demos and reading-undo behavior.

Coverage includes legacy calculation parity, packet framing and serial lifecycle; schema-1 migration, corruption protection and atomic saves; separate physical-camera identities and historical snapshots; live capture destination while navigating other tests; metadata editing while new readings arrive; correction/exclusion revisions; catalogue import review and conflicts; measured-seconds export and bounded parser validation; photograph/original preservation and archive copies; results grouping; PDF pagination and later-assignment provenance.

The original camera-database test log was generated locally at `macos/build/camera-database-test.log` and is not source-controlled. Synthetic PDF preview artifacts are generated by the media tests when `SHUTTER_LOVER_QA_REPORT_BASE` is supplied. The PDF was visually checked for the 3:2 photo, table alignment, headings, pagination and footer placement.

## Interoperability

The actual ArmariumCore public APIs were exercised in a separate temporary harness with synthetic collections and measurements. Armarium accepted Shutter Loved's exported results; retained original interchange bytes and earlier revisions; recognized duplicates; and blocked conflicting same-revision results and the wrong collection. A catalogue exported by Armarium's actual API imported into Shutter Loved and was recognized on a second import. Independent Draft 2020-12 JSON Schema validation also passed.

No user Armarium collection was changed. The Shutter Loved build has no Armarium code or package dependency. See [the interchange notes](SHUTTER_TESTER_JSON.md) for the public contract, limits and repeatable fixture hooks.

## Native camera-database and migration checks (0.2.0)

A separate QA application identity and sandbox were used for synthetic UI checks: catalogue selection and review, camera creation from that import, legacy-session import and explicit assignment, camera metadata saving, photo selection, crop/fit controls, selected-test results and service-event creation. No synthetic test was added to the user's real library.

The normal application bundle was then upgraded. Its existing three sessions and nine readings were retained unchanged as decoded session records, including all seven real readings. The original `sessions.json` and `sessions.pre-camera-library.json` migration backup matched the pre-upgrade bytes exactly. The new library has schema version 2 and a persistent producer UUID. Existing tests remain unassigned until the operator selects the correct physical camera.

The packaged executable is arm64, and code-signature verification passed. The updated app was launched, its visibly labelled Connect tester control checked, and the retained real readings opened in the native inspector.

## Native deletion and restoration checks (0.2.3)

The isolated QA app verified the visible sidebar trash button, the test card's right-click **Delete test…** action, an enabled **File → Delete Test…** command and the workspace delete button. Both empty and populated synthetic tests moved to Trash. A populated test remained in Trash after relaunch and restored with all three readings. The normal app was rebuilt and opened, and its decoded camera library matched the pre-update snapshot exactly; the user's hidden-demo preference and all existing readings were retained.

## Remaining qualification

The user previously confirmed a successful physical Shutter Lover connection. This camera-database update was tested without collecting new physical readings. Busy hardware ports, hub/sleep/wake behavior, the macOS 14 baseline and drag/drop photo handling still need native qualification. Baby Shutter Tester mk II remains an instructional guide, not a supported acquisition protocol.

Photo crop positioning and service-document attachments remain follow-up features; this build supports centered crop-to-fill and fit-entire-photo. Public distribution still requires Developer ID signing and notarization.
